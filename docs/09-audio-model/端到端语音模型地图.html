选型速查

基于当前公开信息
要真·全双工可打断、边听边说
GPT-Live-1 官方明确采用模型级全双工连续交互；Moshi 的双音轨联合建模证据最清楚；MiniCPM-o 4.5、Fun-Audio-Chat-Duplex、RoboBrain-Audio也有官方全双工声明。GPT‑Realtime、Qwen Realtime、豆包及 MinMo、Freeze-Omni属于系统或产品层实现，选型时不要混写。
要全模态输入图像+视频+音频
Qwen3-Omni、MiniCPM-o 4.5、InteractiveOmni、Ming-omni（还能生成图像）；Mini-Omni2覆盖文本、视觉与语音。
要商业实时语音 API直接接入、工具调用
GPT-Realtime-2.1偏复杂语音 Agent 与推理/工具；Qwen-Audio 3.0 Realtime偏纯语音、smart_turn 与克隆音色；豆包实时语音偏中文拟人表达、情绪和演绎。GPT-Live-1目前仅在 ChatGPT 产品中推出，官方表示 API 计划稍后开放。
想拿来当 base 二次开发开源、可训
VITA-Audio(效果好于 GLM-4-Voice、官方推荐当 base)、GLM-4-Voice、OpenS2S(最透明)、SPIRIT LM。
要改 / 克隆音色克隆 or 微调
本地端到端路径优先看 MiniCPM-o 4.5 与 MiMo-Audio；云端 Qwen-Audio 3.0 Realtime与豆包 SeedDuplex 3.0 明确支持复刻音色。若音色一致性比对话建模更重要，仍应优先选择专用 TTS。
口径 先分层，再谈“全双工” 模型结构 ≠ 会话协议 ≠ 产品体验

三层判断

模型级原生要求公开结构能同时维护用户与助手的时间关系；系统 / 产品级可通过 VAD、取消响应、播放器清队列或外挂预测器实现自然插话；流式 / 半双工只说明输入输出能分块，不代表听说真正并发。卡片底部标签按这套口径生成。

证据优先级

  • 本地代码与配置 / 官方仓库
  • 论文或技术报告
  • 官方产品 API 与模型卡
  • 缺少前三类证据时标记“信息有限”

范围：收录能在统一或紧耦合模型链路中完成语音理解与语音生成的代表项目；纯 ASR、纯 TTS 和传统 ASR→LLM→TTS 级联不在本表。商业 API 与闭源产品单独标识，不因产品可用或可调用而推断其内部结构、训练路径或权重开放状态。

交互范式：采用 OpenAI 提出的级联式、轮次式、连续交互三分类。由于本表聚焦端到端语音模型，传统级联式系统不作为模型卡收录；产品层支持持续收音或打断，也不会自动被标成模型级连续交互。

时间：优先采用论文、技术报告或官方首次公开月份。MiMo-Audio 已按 2025.12 正式报告归位；无精确月份的条目在同年内不做强行先后判断。

限制：“可微调”只表示存在公开权重、代码或合理训练路径，不等于低成本；“语音克隆”区分本地模型能力与云 API 能力。卡片是选型索引，不替代各项目的最新模型卡和许可证。
