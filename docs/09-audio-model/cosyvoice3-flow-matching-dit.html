CosyVoice 3 中 Flow Matching 与 DiT 的原理

版本说明：当前仓库中，使用 DiT 作为 Flow Matching 速度场估计器的是 CosyVoice 3。CosyVoice 2 使用卷积/U-Net 风格的 CausalConditionalDecoder。DiT 并不是另一套 Flow Matching 算法，而是负责预测速度场的骨干网络。

1. 整体生成链路

文本
  │
  ▼
LLM 预测 25 Hz 离散 speech token
  │ token embedding，并上采样到 50 Hz
  ▼
Conditional Flow Matching
  ├── 初始状态：高斯噪声 mel
  ├── 条件：speech token、prompt mel、speaker embedding
  └── DiT：预测当前状态的速度
  │ 10 步 ODE 积分
  ▼
80 维、50 Hz mel 频谱
  │
  ▼
HiFT vocoder
  │
  ▼
24 kHz 音频波形

LLM 主要负责离散层面的内容、发音和粗粒度韵律；Flow Matching 负责把这些离散信息还原成连续、细腻的声学特征；HiFT 再把 mel 频谱转换为最终波形。

2. Flow Matching 学习的目标

设：

  • x1：训练数据中的真实 80 维 mel 频谱；
  • z ∼ N(0, I)：与 mel 形状相同的高斯噪声；
  • t ∼ U(0, 1)：随机采样的时间；
  • σmin = 10−6。

CosyVoice 构造一条从噪声到真实 mel 的近似直线路径：

xt = [1 − (1 − σmin)t]z + t x1
  • 当 t = 0 时，xt = z，输入完全是噪声；
  • 当 t = 1 时，xt = x1 + σminz，几乎就是真实 mel。

这条路径对时间求导，得到训练目标速度：

ut = dxt/dt = x1 − (1 − σmin)z

DiT 接收当前状态、时间和所有条件，预测这个速度：

vθ(xt, t, c) ≈ ut

训练损失是有效 mel 区域上的均方误差：

LCFM = E[‖ M ⊙ (vθ(xt, t, c) − ut) ‖22]
随机取“噪声到真实语音”路径上的一个位置，然后告诉模型：站在这里时，应该朝哪个方向、以多快的速度移动。

模型不会直接看到终点 x1 和噪声 z，只能根据当前位置、时间和语音条件预测方向。MSE 的最优解对应给定这些观测时的条件平均速度，该速度场可以把噪声分布连续地运输到条件语音分布。

代码：构造 xt 与目标速度；DiT 预测与 MSE。

3. DiT 在 CosyVoice 3 中的作用

DiT 原名 Diffusion Transformer。它虽然起源于扩散模型，但本质上是一个带时间条件的 Transformer，因此也可以用于预测 Flow Matching 的速度场。

输入维度含义
xt80当前时刻的带噪 mel
mu80由 LLM speech token 得到的连续条件
cond80prompt/reference mel；非 prompt 区域为零
spks80从 192 维 x-vector 投影得到的说话人条件
t标量当前 Flow/ODE 时间

这些输入并不是以相同方式进入 DiT：

  • xt 是 ODE 当前状态，也是 DiT 要处理的主体，严格来说不属于条件；
  • mu、cond 和 spks 通过输入层的逐帧特征拼接进入 DiT；
  • 时间 t 不参与输入特征拼接，而是通过时间嵌入和 AdaLayerNorm 调制每一层。

mu 这个变量名容易被误解：在 CosyVoice 3 中，它是经过嵌入、轻量前瞻处理并上采样后的 speech-token 条件，不是待生成 mel 的均值。

3.1 mu、prompt 和 speaker：逐帧特征拼接

进入 InputEmbedding 前，xt、mu 和 cond 都从 [B, 80, T] 转换为 [B, T, 80]。全局 speaker embedding 则沿时间维复制 T 次。因此，对第 i 个 mel 时间帧，输入为：

qi = [xt,i; condi; μi; espk]

每一项都是 80 维，所以：

qi ∈ R80+80+80+80 = R320

随后，每个 qi 被线性投影为一个 1024 维的 DiT token：

hi = Winqi + b

这里的拼接发生在最后一个 feature/channel 维度，不会增加序列长度。它不是下面这种 prefix-token 方式：

[prompt tokens] [speaker token] [mu tokens] [audio tokens]

实际结构是：

时间帧 1: [x_t,1 | prompt_1 | mu_1 | speaker] → DiT token 1
时间帧 2: [x_t,2 | prompt_2 | mu_2 | speaker] → DiT token 2
时间帧 3: [x_t,3 | prompt_3 | mu_3 | speaker] → DiT token 3
...
  • mu 是离散 speech token 经 embedding、前瞻层处理并由 25 Hz 重复上采样至 50 Hz 后的逐帧条件；
  • cond 是与 mel 等长的 prompt 条件，prompt 区域放入真实参考 mel，其他区域填零；
  • spks 是全局说话人向量，但在拼接前会复制到每个时间帧。

mu 与 mel 的长度关系

原始 speech token 和 mel 的时间长度确实是 1:2。假设原始 speech token 长度为 N：

表征帧率长度
原始 speech token / 前瞻处理后的 token 表征25 HzN
上采样后的 mu50 Hz2N
mel50 HzTmel = 2N

代码没有使用连续插值，而是用 repeat_interleave(2) 将每个 token 表征连续复制两次：

上采样前：[mu_0, mu_1, mu_2, ...]
上采样后：[mu_0, mu_0, mu_1, mu_1, mu_2, mu_2, ...]
h = self.pre_lookahead_layer(token)
h = h.repeat_interleave(self.token_mel_ratio, dim=1)  # token_mel_ratio = 2

因此，应该区分两个阶段：

  • 进入 Flow 模型之前：原始 speech token 与 mel 的长度比为 1:2；
  • 进入 DiT 时：上采样后的 mu 已经与 mel 对齐，二者长度比为 1:1。

若用 μ̃j 表示上采样前第 j 个 token 表征，则：

μi = μ̃⌊i/2⌋

第 i 个 DiT 输入 token 可以更明确地写为：

hi = Win[xt,i; condi; μ̃⌊i/2⌋; espk] + b

speaker 的处理与 mu 不同：它没有原始时间序列，而是把同一个全局说话人向量从 [B, 80] 复制为 [B, T_mel, 80]。最终进入 DiT 时：

输入进入 DiT 时的形状
xt[B, T_mel, 80]
mu[B, T_mel, 80]
cond[B, T_mel, 80]
speaker[B, 80] → [B, T_mel, 80]

pre_lookahead_len=3 表示每个 token 位置可以利用有限的未来上下文，不会把 mu 的长度扩大三倍。长度扩大两倍只来自 token_mel_ratio=2。实现见 flow.py 第 345 行。

投影后的 DiT token 还会叠加因果卷积位置特征。默认模型使用 22 层 Transformer、16 个 attention head、64 维 head 和 2 倍 FFN，最后投影回 80 维速度。

当前配置实际使用普通 DiTBlock。条件采用输入端拼接的 early fusion，而不是独立的 cross-attention。源码虽然实现了 MMDiTBlock，但该配置没有启用它。

3.2 Prompt mel 如何注入 DiT

Prompt mel 也沿特征维注入 DiT，但它只在完整序列的前缀位置非零。它既不是 AdaLayerNorm 条件，也不是额外插入到序列前面的 prefix token。

3.2.1 从 prompt 音频提取三类条件

前端首先把 24 kHz prompt 音频转换成 80 维声学特征：

P ∈ RB × Tp × 80

其中 Tp 是 prompt mel 的帧数。实现见 frontend.py 第 130 行。

同一段 prompt 音频还会产生另外两类信息：

Prompt 信息在 Flow 中的作用
prompt speech token提供离散内容和粗粒度声学信息，并成为 mu 的前缀
prompt mel提供连续、细粒度的参考声学信息，并成为 cond 的前缀
speaker embedding提供全局说话人信息，并复制到所有 mel 位置

3.2.2 构造与完整 mel 等长的 cond

推理时先把 prompt speech token 与待生成的 speech token 沿时间维连接：

token = torch.concat([prompt_token, token], dim=1)

经过 embedding、前瞻层和二倍重复上采样后，形成包含 prompt 与目标区域的完整 mu。设完整 mel 长度为：

T = Tp + Tg

代码创建一个与完整 mel 等长的全零条件矩阵：

cond ∈ RB × T × 80

并只在前 Tp 个位置写入真实 prompt mel：

conds = torch.zeros([1, mel_len1 + mel_len2, 80])
conds[:, :mel_len1] = prompt_feat
condi = Pi, 当 i < Tp；否则 condi = 0
时间位置：  0 ........ T_prompt-1 | T_prompt ........ T_total-1
cond：     [   prompt mel         |          0                ]
mu：       [ prompt speech token  | generated speech token    ]

实现见 flow.py 第 385 行和 flow.py 第 398 行。

3.2.3 在 DiT 输入层逐帧拼接

cond 进入 DiT 后与 xt、mu 和 speaker embedding 沿最后一个 feature/channel 维度拼接：

hi0 = Win[xt,i; condi; μi; espk] + b
Prompt 区域：
[x_t,i | prompt_mel_i | prompt_mu_i | speaker]

生成区域：
[x_t,i |      0       | target_mu_i | speaker]

这不会增加 DiT 的序列长度。实现见 dit.py 第 145 行和 dit.py 第 91 行。

3.2.4 Prompt 信息如何影响后续生成帧

目标生成区域的 cond_i 虽然为零，但 prompt 前缀位置的隐藏状态已经直接接收了 prompt mel。随后，Transformer self-attention 把这些信息传播到后面的生成位置：

prompt mel
   │ 直接注入前缀位置
   ▼
prompt hidden states
   │ self-attention / causal chunk attention
   ▼
后续生成位置
  • 离线模式使用完整 attention，生成位置可以利用 prompt 前缀；
  • 流式模式使用 chunk attention，后续 chunk 可以看到 prompt 与历史 chunk，但不能看到未来 chunk；
  • 因果卷积位置编码也会沿时间方向把局部前缀信息传给后续位置。

所以 prompt mel 不是在每个目标位置重复一份，而是先注入前缀位置，再通过序列建模影响后续 mel，帮助延续参考语音的音色、录音环境和声学风格。

3.2.5 它是软条件，不是硬钳制

CosyVoice 3 的 CausalConditionalCFM 没有在每个 ODE 步骤中执行：

x_t[:, :, :prompt_len] = prompt_mel

也就是说，prompt 区域的 ODE 状态没有被强制替换为真实 prompt mel。完整序列仍从噪声开始：

x_t：  [noise prompt part | noise target part]
cond： [real prompt mel   | zeros]

训练时，提供 prompt 的样本在前缀区域满足 cond = x1 = prompt mel，而损失覆盖完整有效序列。因此模型会学习让最终生成的 prompt 区域接近真实 prompt：

x(1) = [P̂; Ŷ],    P̂ ≈ P

但这里不是严格的 P̂ = P：速度场预测误差、10 步 Euler 积分误差以及 CFG 都可能造成差异，代码也没有在最终输出上执行逐元素覆盖。

DiT 在每个 ODE 步骤都把 prompt mel 当作不随时间变化的条件通道，并生成包含 prompt 区域和目标区域的完整 mel。积分结束后，代码裁掉前 Tp 个生成帧，只把新生成区域交给 vocoder：

feat = feat[:, :, mel_len1:]

实现见 flow.py 第 412 行。因此，更准确的描述是 prefix acoustic conditioning（前缀声学条件），而不是 hard inpainting/clamping（硬性补全或钳制）。

3.2.6 训练时如何学习 prompt conditioning

训练时从真实 mel 的开头随机选取一段作为 cond：

conds = torch.zeros(feat.shape)
index = random.randint(0, int(0.3 * feat_len))
conds[i, :index] = feat[i, :index]
  • 大约一半训练样本不提供 prompt mel；
  • 其余样本从整段语音的前 0～30% 随机选取真实 mel 前缀；
  • Flow Matching 仍以整段真实 mel 为目标，模型由此学会利用声学前缀继续生成；
  • CFM 的 20% classifier-free condition dropout 还可能同时清零 mu、cond 和 speaker，以便推理时计算有条件与无条件速度。

实现见 flow.py 第 350 行和 flow_matching.py 第 184 行。

prompt mel → 写入 cond 的前缀位置 → 与 xt、mu、speaker 逐帧拼接 → 通过 self-attention 影响后续生成

3.3 时间 t：逐层调制

与上述逐帧特征不同，标量时间 t 不会被拼入 qi，也不会形成一个时间 prefix token。它经过正弦位置编码和 MLP，生成一个全局时间向量，再送入每一个 DiT Block 的 AdaLayerNorm，并在最终输出归一化层中再次使用。下一节给出具体过程。

代码：输入融合；DiT 配置。

4. 时间条件如何控制 DiT

正弦时间编码 → MLP → 1024 维时间向量

每一个 DiT Block 都通过 AdaLayerNorm 使用该时间向量：

ĥ = LN(h) ⊙ (1 + s(t)) + b(t)
h ← h + gattn(t) Attention(ĥ)
h ← h + gffn(t) FFN(ĥ)

因此，同一个 Transformer 在不同时间点会执行不同的变换：

  • t 较小时，输入更接近噪声，网络主要建立粗粒度语音结构；
  • t 较大时，输入已接近 mel，网络更多地修正局部细节；
  • speech token 约束内容和粗粒度韵律；
  • speaker embedding 与 prompt mel 约束说话人音色和参考声学信息。

代码：DiTBlock 与 AdaLayerNorm 门控。

5. 推理：从噪声积分到 mel

推理从高斯噪声开始，并求解常微分方程：

x(0) = z,    dx/dt = vθ(x, t, c)

CosyVoice 当前实现使用 10 步 Euler 积分：

xk+1 = xk + (tk+1 − tk) vθ(xk, tk, c)

积分时间点经过 cosine 调度。完成 10 步后，x(1) 就是生成的 mel，随后交给 HiFT vocoder。

它与传统 DDPM 的主要区别是：

  • DiT 输出的是速度 dx/dt，而不是 DDPM 中常见的噪声 ε；
  • 推理求解确定性 ODE，不会在每一步重新加入随机噪声；
  • 训练时可以直接采样任意 t，无需逐步执行前向加噪；
  • 条件路径较直接，因此少量 ODE 步数也能工作。

当前 CausalConditionalCFM 使用预先生成的固定噪声表，而不是每次重新采样噪声。这让流式分块和整段推理能够在相同位置使用一致的初始噪声。

代码：Euler 积分；10 步设置；固定噪声。

6. Classifier-Free Guidance

训练时以 20% 的概率同时清零 speech-token、speaker 和 prompt 条件，使同一个 DiT 同时学习有条件速度与无条件速度。推理时组合为：

vCFG = (1 + w)vcond − w vuncond

默认 w = 0.7，因此：

vCFG = 1.7vcond − 0.7vuncond

这会增强生成结果对 speech token、说话人音色和 prompt 的服从程度。

代码：训练条件丢弃；推理 CFG 组合。

7. 流式生成

  • 离线模式使用完整时间上下文；
  • 流式模式使用 chunk attention mask，不能看到后续 chunk；
  • 25 个 speech token 扩展成 50 个 mel frame，即大约 1 秒的声学 chunk；
  • 输入侧允许 3 个 speech token 的有限前瞻；
  • 因果卷积位置编码不会读取未来帧；
  • 训练时随机切换流式和非流式模式，使同一模型兼容两种推理方式。

代码：统一流式/非流式训练；chunk attention mask。

8. 为什么使用 Flow Matching + DiT

  1. 训练目标简单：把生成建模转化为有监督的速度回归。
  2. 采样步数较少：近似直线路径配合 ODE，仓库默认只使用 10 步。
  3. 长时建模能力强：Transformer attention 适合捕获较长范围的韵律和声学关系。
  4. 容易扩大容量：DiT 可以通过增加宽度、层数和 attention heads 扩展。
  5. 时间条件自然：AdaLayerNorm 让每一层根据当前噪声阶段动态工作。
  6. 兼容流式生成：因果卷积和 chunk attention mask 限制未来信息。
  7. 条件控制统一：speech token、prompt mel 和 speaker embedding 共同控制同一个速度场。

9. 一句话总结

CosyVoice 3 先让 LLM 给出“要说什么”的离散 speech token，再让时间条件化的 DiT 学习一个速度场，用 10 步 ODE 把高斯噪声运输成符合 token、音色和 prompt 的连续 mel 频谱。
